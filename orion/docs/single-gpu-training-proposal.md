# 单 GPU ALFWorld 训练提案（尚未批准实现）

用户明确：每个实验作业只用一张 GPU，时限不超过18h；独立作业并行、
有产物依赖的作业用 Slurm dependency 串行。不得再提出恢复8卡作为默认路径。
现有学生/教师基线脚本符合这个限制，可以独立推进。

本地证据：config_validator.py 把 rollout 与 auxiliary GPU 数相加，再从
总 GPU 数中扣除以分配 trainer；common/models/__init__.py 给推理引擎申请
独立整卡 placement bundles；verl_trainer.py 单独创建训练资源池。
所以只改 sbatch 为1卡或把时限延长到18h不能满足现有调度约束。

拟新增默认关闭的串行执行入口：学生生成一批轨迹，卸载学生推理资源；
教师按原 workflow 的上下文/切片给相同学生token评分，卸载教师；
复用原 advantage、train_step、loss、optimizer、scheduler 更新学生，再进入
下一批。训练状态在阶段间和恢复时必须完整保存，不能每次重置optimizer。
张量并行和序列并行设为1，实际有效 batch、提示词、解析器、奖励、评分上下文
及训练目标保持；不以独立 Transformers 短诊断冒充原生训练。

必须显式报告的差异：原异步并发变成串行阶段，样本滞后和权重版本分布改变；
并行度改变可能引入浮点差异。保留loss不等于保留整个训练过程，更不保证
与8卡数值等价。分时加载有额外IO及运行时间，尚无单卡训练耗时/显存实测。

实现前待用户具体批准。获准后先审核原样本过滤/组批/消费顺序及权重同步接口，
再实现最小入口；若必须进一步改变batch、mask、采样或截断策略，先报告，
不得自行缩减。验证先2步，再依赖其成功checkpoint恢复到4步；记录实际
optimizer更新次数、消费样本、评分对齐和恢复状态，再决定50步pilot。
第一阶段仅1.7B学生与8B教师，不默认扩大模型规模，不自动运行E5/E6。
